# Null-agent measurement on external agent benchmarks: candidate list

Desk research, 2026-10-27. Nothing was installed or run. Every number below is either quoted from a cited source or explicitly labelled as an estimate. Estimates (engineer time, money) are planning figures only, not measurements.

Reference point (results/null_agent/tau2_null_agent.md, tau2-bench commit `989d3285`): an agent that does nothing passes 23 of 50 airline tasks (46.0%), 6 of 114 retail tasks (5.3%) and 0 of 2,285 telecom tasks under the stock scorer.

Terms used below:
- **Null agent**: submits nothing (empty trajectory, empty answer, empty patch, or ends at step 0).
- **Refusal agent**: does nothing except give the benchmark's "cannot be done" answer (for example `FAIL` in OSWorld, `N/A` in WebArena, no function call in BFCL). This is a second, equally cheap baseline wherever the benchmark rewards a correct refusal.
- **By construction**: the score follows from the scoring code and the task definitions alone, without running anything.

## 1. tau-bench (original)

1. **Repository and version.** https://github.com/sierra-research/tau-bench. Last commits 2026-03-18 (`59a200c`, README now warns that the tasks are outdated and points to the successor repository) and 2025-08-28 (`4754e6b`) (https://github.com/sierra-research/tau-bench/commits/main). The README states the tasks "are not updated" (https://github.com/sierra-research/tau-bench). Task counts: 115 retail, 50 airline (paper, Table 1: https://arxiv.org/html/2406.12045).
2. **Scoring.** State diff plus substring check. `calculate_reward` in `tau_bench/envs/base.py` hashes the database after the agent's run, reloads the initial database, replays the ground-truth actions, and compares the two hashes; if the task lists `outputs`, each must appear (case-insensitive, commas removed) in the agent's `respond` messages (https://github.com/sierra-research/tau-bench/blob/main/tau_bench/envs/base.py). The paper defines reward = r_action × r_output (https://arxiv.org/html/2406.12045).
3. **Can a null agent score.** Yes, by construction, on every task whose ground-truth actions contain no write (read actions do not change the hash) and whose `outputs` list is empty. Count not published. tau2-bench airline was derived from these tasks and gives 23/50 for the null agent; a secondary source describing the tau2 airline port reports the same 23 tasks with an empty write list, including refusal tasks (https://docs.nvidia.com/nemo/labs-voice-agent/evaluate-voice-agents/domain-guides/tau-2-airline). The original-repo count can differ because the original task files were later corrected in the successor (https://github.com/sierra-research/tau-bench).
4. **What is needed offline.** Repository only (task files are Python modules in the repo); no Docker, no VM. The database check needs no model call. Estimated engineer time: 2–4 hours (the tau2 null scanner logic carries over: count tasks with no write action and empty outputs, then confirm by calling `calculate_reward` on an untouched environment).
5. **Money.** Null number: $0 (estimate). Documented baseline run: Holistic Agent Leaderboard (HAL), TAU-bench Airline, "TAU-bench Tool Calling" with Gemini 2.0 Flash High: 28.00% accuracy for $0.31 total; DeepSeek V3: 44.00% for $5.43; the page warns that reported costs are overstated (https://hal.cs.princeton.edu/taubench_airline).
6. **Relevance.** HAL still ranks agents on the original airline tasks, where a cheap model's 28.00% may sit below the null floor (the floor is not yet measured on the original files; tau2's 46.0% is only indicative). This is a direct "exam, not model" case.

## 2. AppWorld

1. **Repository and version.** https://github.com/StonyBrookNLP/appworld; PyPI `appworld` 0.1.3.post1, released 2026-02-17 (https://pypi.org/project/appworld/). 750 tasks, 9 apps, 457 APIs (https://arxiv.org/abs/2407.18901); splits Train 105, Dev 60, Test-Normal 168, Test-Challenge 417 (https://arxiv.org/html/2407.18901, Section 3.4).
2. **Scoring.** State diff via unit tests: "database-state-based unit tests to check if the agent completed the task correctly without causing any collateral damage" (https://github.com/StonyBrookNLP/appworld); question tasks (about 15%) also carry a fixed ground-truth `answer` field (https://arxiv.org/html/2407.18901, Section 3.1). Metrics: task goal completion and scenario goal completion (`tgc`, `sgc`) (https://github.com/StonyBrookNLP/appworld).
3. **Can a null agent score.** Not expected by construction: non-question tasks require a state change, question tasks require an answer. The collateral-damage tests pass trivially for a null agent, so any task whose required-change tests happen to be satisfied by the initial state would pass. The paper validates that the reference solution passes the tests (https://arxiv.org/html/2407.18901, Section 3.3); no statement was found that the tests were checked against a no-op solution, so the null number is an open question, expected near 0.
4. **What is needed offline.** `pip install appworld`, `appworld install`, `appworld download data` (download size not stated); Docker optional; evaluation is local: `appworld evaluate {experiment_name} {dataset_name}` (https://github.com/StonyBrookNLP/appworld). No model call is described in evaluation. Estimated engineer time: 0.5–1 day (produce an empty experiment output per task, run the evaluator). Requires installing a third-party package in a separate folder.
5. **Money.** Null number: $0 (estimate). Baseline cost with a cheap model: not documented in the sources found.
6. **Relevance.** A well-designed state-diff exam with explicit collateral-damage tests; a near-zero null number would serve as the positive contrast to tau-bench ("the same kind of exam, built differently, does not reward inaction").

## 3. WebArena and WebArena-Verified

1. **Repository and version.** Original: https://github.com/web-arena-x/webarena, 812 tasks from 241 templates (https://arxiv.org/html/2307.13854). Audited re-release: https://github.com/ServiceNow/webarena-verified (PyPI release 2026-01-07, Docker/uvx distribution announced 2026-02-02; 812 audited tasks plus a hard subset) (https://github.com/ServiceNow/webarena-verified). The hard subset is 137 tasks in the paper abstract (https://neurips.cc/virtual/2025/124576) and 258 tasks in the repository (https://github.com/ServiceNow/webarena-verified); the two sources disagree.
2. **Scoring.** Original: hybrid. `StringEvaluator` (exact_match, must_include, fuzzy_match via an LLM), `URLEvaluator`, `HTMLContentEvaluator` (https://github.com/web-arena-x/webarena/blob/main/evaluation_harness/evaluators.py); the paper used gpt-4-0613 for fuzzy matching on 82 examples (https://arxiv.org/html/2307.13854). Verified: deterministic; LLM judging and substring matching removed; backend state verified for state-changing tasks; structured JSON answer with explicit status codes (https://neurips.cc/virtual/2025/124576, https://github.com/ServiceNow/webarena-verified). Status values include `SUCCESS | NOT_FOUND_ERROR | PERMISSION_DENIED_ERROR | ACTION_NOT_ALLOWED_ERROR`, replacing the old catch-all "N/A" (https://github.com/cua-lite/cua-lite/issues/50).
3. **Can a null or refusal agent score.** Original: unachievable tasks expect the answer "N/A" (https://arxiv.org/html/2307.13854, Section 3.2); a refusal agent that always answers "N/A" passes them by construction, an empty answer does not. The count is not stated in the paper; the SR_UA values in its Table 2 (8.33, 27.78, 38.89, 44.44, 58.33, 77.78) are all multiples of 1/36, which is consistent with 36 unachievable tasks in that paper version (inference, not a published figure); one secondary source states 161 (https://beancount.io/bean-labs/research-logs/2026/06/14/webarena-realistic-web-environment-autonomous-agents), unverified and inconsistent with the 1/36 pattern. The exact count must be taken from the task file (`test.raw.json`). Verified: the refusal-type status codes make a "status-only" agent the natural baseline; a step-limit truncation "submits no response (scores 0)" (https://github.com/cua-lite/cua-lite/issues/50). Null passes on navigation or content tasks whose check is satisfied by the start page are possible in the original harness but undocumented.
4. **What is needed offline.** Verified: scoring is "re-computable offline from an agent's final response plus a HAR network trace", without live sites (https://github.com/cua-lite/cua-lite/issues/50, https://github.com/ServiceNow/webarena-verified); a null/refusal measurement needs no Docker and no model call. Estimated engineer time: 0.5–1 day. Original harness: self-hosted sites, about 60 GB of images plus about 200 GB of map assets (Verified images up to 92% smaller, e.g. GitLab 31.6 GB vs 155 GB; Wikipedia and map data about 100 GB and 60 GB) (https://github.com/cua-lite/cua-lite/issues/50); estimated 2–4 days.
5. **Money.** Verified null/refusal number: $0 (estimate). Original harness with live sites: a cloud machine with several hundred GB of disk for 1–2 days, estimated tens of dollars; fuzzy_match calls an LLM judge (cost small, not documented). Baseline cost with a cheap model: not documented; the Verified hard subset is reported to cut evaluation cost by 83% (https://neurips.cc/virtual/2025/124576).
6. **Relevance.** The same benchmark scored by two harnesses (original vs Verified) allows "same tasks, different exam" comparisons; the reported failure mode of over-refusal (https://beancount.io/bean-labs/research-logs/2026/06/14/webarena-realistic-web-environment-autonomous-agents, secondary) makes the refusal baseline informative.

## 4. OSWorld / OSWorld-Verified

1. **Repository and version.** https://github.com/xlang-ai/OSWorld; OSWorld-Verified released 2025-07-28 (https://github.com/xlang-ai/OSWorld). 369 tasks, 30 infeasible (8.1%); 361 when the 8 Google Drive tasks are excluded (https://www.aiwiki.ai/wiki/osworld, https://epoch.ai/blog/osworld).
2. **Scoring.** Execution-based state checks: `DesktopEnv.evaluate()` in `desktop_env/desktop_env.py` calls per-task getters and metrics (with and/or conjunctions); for `func == "infeasible"` the score is 1 if the last action is `FAIL`, else 0; for every other task a final `FAIL` returns 0 before any metric runs (https://github.com/xlang-ai/OSWorld/blob/main/desktop_env/desktop_env.py). No model call appears in `evaluate()`; the metric modules were not inspected.
3. **Can a null or refusal agent score.** Refusal agent (emit `FAIL` at step 0): 30/369 = 8.1% by construction, from the code above and the infeasible count. An agent paper notes that agents which "default to outputting fail only upon reaching the step limit" collect these points (https://arxiv.org/pdf/2601.07779). Null agent (emit `DONE` at step 0): passes every task whose checker is satisfied by the initial state. An independent review reports tasks that "don't ask for any action", overly lax checkers (one only checks that zoom decreased), and about 10% of tasks with serious errors (https://epoch.ai/blog/osworld). Count unknown until measured.
4. **What is needed offline.** The refusal number needs only the task JSON files (count `func: "infeasible"`): no VM, minutes. The null number needs the VM: VMware Workstation Pro or VirtualBox, Docker with KVM, or AWS; Python 3.10+ (https://github.com/xlang-ai/OSWorld). VM image size not stated by the maintainers (a third-party repackaging is 11.7 GB: https://hub.docker.com/r/synacktra/osworld-ubuntu). Some tasks need live internet or a Google account (https://epoch.ai/blog/osworld). Estimated engineer time: 1–3 days (null run = task setup + evaluator on an untouched VM, 369 times).
5. **Money.** Refusal number: $0. Null number: $0 on a local machine with virtualization; on AWS, estimated tens of dollars (host plus per-task instances; one paper ran 40 parallel instances per c4.8xlarge host: https://arxiv.org/pdf/2510.02250). Baseline run: one paper reports $0.72 per task in API cost for a single rollout of its own agent (https://arxiv.org/pdf/2510.02250), i.e. roughly $260 for 361 tasks (arithmetic estimate, not a cheap-model figure).
6. **Relevance.** The scoring code itself grants 8.1% to an agent that gives up immediately, and the null run tests whether the initial state already satisfies checkers: two exam properties independent of the model.

## 5. BFCL (Berkeley Function Calling Leaderboard)

1. **Repository and version.** https://github.com/ShishirPatil/gorilla/tree/main/berkeley-function-call-leaderboard; PyPI `bfcl-eval` 2026.3.23 (https://pypi.org/project/bfcl-eval/); BFCL V4 released 2025-07-17 (https://github.com/ShishirPatil/gorilla/blob/main/berkeley-function-call-leaderboard/CHANGELOG.md); leaderboard last updated 2026-04-12 (https://gorilla.cs.berkeley.edu/leaderboard.html).
2. **Scoring.** Mostly deterministic AST matching and execution; multi-turn entries checked by a state/response checker (`_evaluate_single_multi_turn_entry`). For irrelevance categories, `_evaluate_single_relevance_entry` treats a decode failure or empty decoded output as "no function call" and sets `success = not contain_func_call` (https://github.com/ShishirPatil/gorilla/blob/main/berkeley-function-call-leaderboard/bfcl_eval/eval_checker/eval_runner.py). Overall score = Agentic × 40% + Multi-Turn × 30% + Live × 10% + Non-Live × 10% + Hallucination × 10%; Hallucination is the unweighted average of Non-Live Irrelevance (240) and Live Irrelevance (882), 1,122 entries; Live Relevance is "No Score Impact" (https://gorilla.cs.berkeley.edu/blogs/15_bfcl_v4_web_search.html, https://evalscope.readthedocs.io/en/latest/third_party/bfcl_v4.html).
3. **Can a null agent score.** Yes, by construction: an empty response passes all 1,122 irrelevance entries, so Hallucination = 100% and the null agent receives 10.0 of 100 overall points before any other category is counted. The only category that would penalise "never call anything" (relevance detection: 18 live entries at V2 release, https://gorilla.cs.berkeley.edu/blogs/12_bfcl_v2_live.html) does not enter the overall score. Multi-turn and agentic categories are expected near 0 for an empty response (not verified). Category sizes: 240 irrelevance (https://gorilla.cs.berkeley.edu/blogs/8_berkeley_function_calling_leaderboard.html), 882 live irrelevance at V2 release (https://gorilla.cs.berkeley.edu/blogs/12_bfcl_v2_live.html); a third-party mirror lists 875 (https://huggingface.co/datasets/bengaliAI/BFCL/blob/main/README.md), and the changelog records a fix touching 70 live-irrelevance entries (CHANGELOG link above).
4. **What is needed offline.** Python package plus bundled data; `bfcl evaluate --model ... --test-category ...` scores previously generated result files (https://github.com/ShishirPatil/gorilla/tree/main/berkeley-function-call-leaderboard). No Docker. No model call needed for scoring; the web_search category needs a SerpAPI key only for generation. Estimated engineer time: 2–4 hours (write empty result files in the expected format for every category, run the evaluator).
5. **Money.** Null number: $0 (estimate). Baseline: the leaderboard reports an estimated full-benchmark cost per model in USD ("Cost is calculated as an estimate of the cost for the entire benchmark") (https://gorilla.cs.berkeley.edu/leaderboard.html); the values were not extracted here.
6. **Relevance.** The overall formula assigns 10% of the leaderboard score to a column that silence maximises and drops the column that would penalise silence: a pure exam-design effect, computable for free.

## 6. SWE-bench Verified

1. **Repository and version.** https://github.com/SWE-bench/SWE-bench (no tagged releases shown; newest dated news 2026-09-01). 500 human-validated tasks (https://openai.com/index/introducing-SWE-bench-verified/, https://github.com/SWE-bench/sb-cli).
2. **Scoring.** Unit tests in Docker: a patch resolves a task if the FAIL_TO_PASS tests pass and the PASS_TO_PASS tests still pass (https://openai.com/index/introducing-SWE-bench-verified/). Harness: `swebench eval verified -p <predictions> --run-id <id>`; `--gold` runs the reference patches (https://github.com/SWE-bench/SWE-bench).
3. **Can a null agent score.** Not by construction: FAIL_TO_PASS tests are defined as failing before the reference patch. A null run is still a useful audit: any task whose FAIL_TO_PASS tests pass on the unpatched repository (flaky or environment-dependent tests; the announcement notes setup problems that make tests fail "regardless of the solution", the mirror case) would be exposed. Expected count: 0 or very small.
4. **What is needed offline.** x86_64, at least 120 GB free disk, 16 GB RAM, 8 cores; Docker (https://github.com/SWE-bench/SWE-bench). No model call. Cloud alternatives: sb-cli (AWS) and Modal (same source). Note: the harness may short-circuit an empty patch instead of running tests; a trivial no-op patch (for example a whitespace change in a non-test file) would be needed to force the test run (to be checked in the harness). Estimated engineer time: 1 day plus several hours of compute.
5. **Money.** Null number: $0 locally; cloud cost not documented (estimate: a few dollars on Modal or sb-cli quota). Baseline: around $0.30 per instance for a mixed frontier-model mini-SWE-agent run, i.e. roughly $150 for 500 tasks (https://www.swebench.com/post-250820-mini-roulette.html); HAL SWE-bench Verified Mini (50 tasks) lists a DeepSeek R1 run at $4.16 total with 0% resolved (https://hal.cs.princeton.edu/swebench_verified_mini).
6. **Relevance.** Negative control: an exam where the null agent should score 0 by design; a non-zero result would be a strong finding, a zero result shows the measurement discriminates.

## 7. Terminal-Bench 2.0

1. **Repository and version.** Tasks: https://github.com/harbor-framework/terminal-bench-2 (89 task directories counted on the page); harness: Harbor, https://github.com/laude-institute/harbor; run with `harbor run --dataset terminal-bench@2.0 ...` (https://github.com/laude-institute/harbor). Paper: https://arxiv.org/abs/2601.11868v1. A 2.1 revision fixes 28 tasks of 2.0 (https://www.snorkel.ai/blog/terminal-bench-2-0/). Beta line terminal-bench-1: https://github.com/laude-institute/terminal-bench.
2. **Scoring.** Unit tests: each task ships a test script run in the task container after the agent finishes; each task has a human-written oracle solution (https://github.com/laude-institute/terminal-bench, https://huggingface.co/papers/2601.11868).
3. **Can a null agent score.** Only if a task's tests pass on the initial container state; not expected by design, count unknown. Harbor ships a no-op agent (`src/harbor/agents/nop.py`, next to `oracle.py`) (https://github.com/harbor-framework/harbor/tree/main/src/harbor/agents), so the null measurement is a supported run mode. Validation is described as checking solvability with the oracle (https://github.com/harbor-framework/terminal-bench-2); no check against a no-op agent is mentioned there.
4. **What is needed offline.** Docker (local) or a cloud sandbox provider such as Daytona or Modal (https://github.com/laude-institute/harbor). No model call with the nop agent. Image sizes not stated. Estimated engineer time: 0.5 day plus image build time.
5. **Money.** Null number: $0 locally; small sandbox cost on a cloud provider (estimate, under $10). Baseline cost with a cheap model: not documented in the sources found.
6. **Relevance.** A second negative control from a different domain (terminal tasks), with the null agent built into the official harness: cheap and hard to dispute.

## 8. GAIA

1. **Repository and version.** Dataset: https://huggingface.co/datasets/gaia-benchmark/GAIA (gated; validation answers public, test answers private; 110 MB; format update to Parquet in October 2025); paper 2023-11-21; "more than 450" questions (same page). Scorer: https://huggingface.co/spaces/gaia-benchmark/leaderboard/blob/main/scorer.py.
2. **Scoring.** Normalised exact match: numbers compared after stripping `$`, `%`, commas; lists split on comma/semicolon and compared element-wise; strings lowercased with whitespace and punctuation removed (scorer link above).
3. **Can a null agent score.** Only where the ground truth normalises to an empty string (an empty answer is not converted to "None"); a "None" answer matches only a ground truth that normalises to "none" (scorer link above). Expected 0 or near 0 on the public validation split; a refusal-style answer ("None", "0") is the more interesting probe.
4. **What is needed offline.** Accept the dataset gate on Hugging Face (a manual step for the account owner), download 110 MB, run the scorer on empty and refusal answers for the validation split. No Docker, no model call. Estimated engineer time: 1–2 hours. Test split cannot be measured offline (answers private).
5. **Money.** Null number: $0. Baseline: HAL GAIA, HAL Generalist Agent with Gemini 2.0 Flash, 32.73% for $7.80 (costs flagged as overstated) (https://hal.cs.princeton.edu/gaia).
6. **Relevance.** Low: a pure answer-match exam, included as a cheap control.

## 9. ToolSandbox

1. **Repository and version.** https://github.com/apple/ToolSandbox (2 commits shown, no dates or releases visible); paper https://arxiv.org/abs/2408.04682. 1,032 test scenarios, 224 in the Insufficient Information category (https://arxiv.org/html/2408.04682, Tables 4 and 6).
2. **Scoring.** Deterministic milestone/minefield similarity: milestones form a DAG with per-milestone similarity measures (exact match, ROUGE-L on messages, AST match on tool traces); any minefield hit sets the whole trajectory score to 0 (https://arxiv.org/html/2408.04682, Equation 1; https://github.com/apple/ToolSandbox). The user is simulated by an LLM (GPT-4o in the examples), not used for scoring.
3. **Can a null agent score.** Partly. Score is continuous, so the null number is a mean similarity, not a pass count. In Insufficient Information scenarios minefields (fabricated tool calls) are never triggered by a null agent; milestones may still be unmet. The paper notes that weaker models that rarely called tools scored higher in this category and calls it "a side effect instead of a positive outcome" (https://arxiv.org/html/2408.04682).
4. **What is needed offline.** Python repository; no Docker. Scoring needs no model call; whether a null run triggers user-simulator calls depends on how the episode terminates (to be checked). Estimated engineer time: 0.5–1 day.
5. **Money.** Null number: $0 if the episode can end without simulator turns; otherwise a few dollars of simulator calls (estimate). Baseline cost: not documented.
6. **Relevance.** The paper itself reports that abstaining is rewarded in one category, which matches the thesis; the continuous score makes the result less crisp than a pass count.

## Not shortlisted (brief)

- **AgentBench** (https://github.com/THUDM/AgentBench): eight heterogeneous environments with separate Docker stacks; high setup cost for a null measurement, and per-environment scoring differs.
- **VisualWebArena, WorkArena, TheAgentCompany, Mind2Web-Live**: either share WebArena's harness logic (VisualWebArena), need a live ServiceNow instance (WorkArena) or a large multi-service Docker stack with partly LLM-graded checkpoints (TheAgentCompany), or depend on live websites (Mind2Web-Live). Higher cost per null number than the candidates above.

## Ranked recommendation (3–4 benchmarks)

1. **BFCL V4.** Strongest by-construction result: 10.0 of 100 overall points for an empty response, from the published formula and the scoring code; offline, no Docker, about half a day, $0. Shows an exam-design choice (score silence, ignore the penalty for silence) in a widely cited leaderboard.
2. **tau-bench (original).** Same scorer family as tau2, still used by HAL, where a cheap-model run is listed at 28.00%; the null floor on the original task files is a few hours of work and $0, and it shows that the problem was inherited, not introduced.
3. **OSWorld-Verified.** Two numbers: refusal agent 30/369 = 8.1% by construction (minutes, $0), and the null agent on the initial VM state (1–3 days, $0 locally or tens of dollars on AWS), where independent reviews already report lax checkers and tasks without required action. Different modality (desktop GUI).
4. **WebArena-Verified** (alternative: Terminal-Bench 2.0). Offline HAR re-scoring makes null and status-only refusal baselines free and Docker-free; the original-vs-Verified pair gives "same tasks, different exam". If a negative control is preferred over a fourth positive case, Terminal-Bench 2.0 with Harbor's built-in no-op agent is the cheapest one (half a day, $0 locally).
