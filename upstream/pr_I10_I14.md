# NL-assertion evaluator: parse fenced or array judge replies; one verdict per assertion, a missing verdict counts as unmet

Status: draft, not opened. Patch: `patches/I10_I14.patch` (paths relative to the repository root; base tag `v2.0.0`, commit `989d3285ae669e49503324bdb9981bf14fccedeb`). Issue text: `issue_I9_I10_I14_nl_assertion_judge.md` (parts I10 and I14; the transcript view of part I9 is not changed here).

## Description

`NLAssertionsEvaluator.evaluate_nl_assertions` parsed the judge reply with `json.loads(content)` followed by `.get("results", [])`, and built one check per returned result. A reply inside a markdown code fence raised `JSONDecodeError`, a bare top-level JSON array raised `AttributeError`, and in a live run either error restarts the whole simulation and, after the last attempt, records it as an infrastructure error. The reward was `all(met)` over the returned results, so an assertion the judge omitted counted as met, and an empty `results` list gave reward 1.0.

Changes, all in `src/tau2/evaluator/evaluator_nl_assertions.py`:

- `parse_judge_results(content)`: accepts `{"results": [...]}` or a bare array of results, either one optionally inside a ```` ``` ```` / ```` ```json ```` fence; raises `ValueError` (which includes `JSONDecodeError`) when the reply has no list of result objects. The NL evaluator did not use `extract_json_from_llm_response`, and that helper is left unchanged because other judges rely on it.
- `match_judge_results(nl_assertions, results)`: returns exactly one `NLAssertionCheck` per assertion, in assertion order. A result belongs to the assertion whose text it echoes (whitespace and case ignored); results that echo no assertion are paired by position with the remaining assertions when the counts are equal; an assertion left without a result is unmet, with the justification "The judge returned no verdict for this assertion."
- `evaluate_nl_assertions` uses the two helpers. `FullDuplexNLAssertionsEvaluator` delegates to it, so both modes change. The judge prompt and model are unchanged.

New tests in `tests/test_evaluator/test_nl_assertions_reply_parsing.py`: four accepted reply formats; an omitted assertion is unmet; an empty `results` list fails every assertion; verdicts are matched by text, not by reply order; a paraphrased echo falls back to position; a reply without results raises.

## Risk

- With the stock judge, replies that were already plain JSON objects echoing every assertion get the same verdicts as before; the checks are now listed in assertion order instead of reply order.
- Simulations that used to fail evaluation on a fenced or array reply are now scored instead of retried and excluded, so for judges that produce such replies the denominator and the score can change.
- A judge reply that omits assertions now lowers the reward instead of passing them. This is the intended correction, but it can lower scores where a judge habitually returns partial lists.
- The positional fallback applies only when the leftover counts match; a judge that both paraphrases and reorders its echoes could be mismatched. Numbering the assertions in the prompt and asking for an index would remove that case; it changes the prompt, so it is not part of this patch.
