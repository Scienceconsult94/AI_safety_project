No task in the batch has `replay_errors` > 0 or `write_noop_ids`, so 1b and 1c are not decided. Defect rows: 2 (20/4c, 21/4c, both medium). Uncertain: 22/2e, 26/4a.

**Cross-cutting finding (tasks 20, 21).** `modify_pending_order_items` (tools.py l.578–584) writes `item.price = variant.price` and `item.options = variant.options` with `variant` left over from the last iteration of the first loop (l.550). Every modified item therefore stores the price and options of `new_item_ids[-1]`, and the target hash depends on the order of the (item, new item) pairs inside the one call. The scenario never fixes that order, so a correct call that lists the same pairs in another order scores 0. probe_2h does not cover this (it permutes whole WRITE calls). `diff_price` is also summed without rounding (l.556), so `payment_history.amount` can additionally differ in the last bits.
